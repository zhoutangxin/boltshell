# ssh-go 开发调试、正式部署与前后端关联

本文说明 Wails v2 是什么、如何安装 Wails 工具、如何在本机调试、如何打成 Windows / macOS / Linux 可运行文件，以及 Vue 页面如何调用 Go 后端。

---

## 1. 程序是什么

这是一个 **Wails v2 桌面应用**：

- **后端**：Go（SSH、SQLite、配置）
- **前端**：Vue 3 + Vite + xterm.js（连接管理、终端）
- **打包后**：Windows 为 `ssh-go.exe`，macOS 为 `ssh-go.app`，Linux 为 `ssh-go`；双击 / 直接运行即可，用户电脑不用装 Go、Node

### 1.1 Wails v2 是什么

**Wails v2** 是一套用 **Go 写后端、用网页技术写界面** 的桌面应用框架。ssh-go 就是用它做的。

简单说：

- **后端**：Go（本项目的 SSH、SQLite 都在这里）
- **前端**：HTML / CSS / JS，本项目用 Vue 3
- **打包结果**：用户电脑不用装 Go、Node。各系统产物不同：
  - **Windows**：`ssh-go.exe`，双击就能跑（系统需有 WebView2，Win10/11 一般自带）
  - **macOS**：`ssh-go.app`，双击就能跑（系统自带 WKWebView）
  - **Linux**：`ssh-go` 可执行文件（需要 GTK / WebKitGTK 运行库）

源码是一份，三个系统都能编。**但桌面窗口依赖本机 WebView / CGO，通常要在目标系统上打包**：Windows 上打 Windows 包，Mac 上打 Mac 包，Linux 上打 Linux 包。不能指望在 Windows PowerShell 里直接打出能用的 `.app`。

它解决的是：不想单独做一套 Win32 / Qt / AppKit 界面，又想把网页 UI 嵌进桌面窗口里。Wails 会：

1. 起一个桌面窗口（Windows = WebView2，macOS = WKWebView，Linux = WebKitGTK）
2. 把 Vue 页面显示在窗口里
3. 让前端直接调 Go 方法（如 `ListConnections`、`StartSession`），不用自己写 HTTP API

所以本项目 **不是传统的「浏览器网站 + 独立 API 服务」**。没有 `/api/xxx`，Chrome Network 的 Fetch/XHR 里看不到接口。前端跑在内嵌 WebView（或开发时的浏览器）里，通过 Wails 绑定 / IPC 直接调 Go。

**v2** 是第 2 代。本项目用的是 **v2.15.0**，安装 CLI 时要带上版本号：

```powershell
go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0
```

`wails` / `wails.exe` 只是脚手架（`wails dev` / `wails build`）；真正给用户用的是打出来的 `ssh-go.exe` / `ssh-go.app` / `ssh-go`。

```
┌─────────────────────────────────────────┐
│                 ssh-go                  │
│  ┌─────────────┐     ┌───────────────┐  │
│  │  Vue 页面    │ ←→  │  Go App      │  │
│  │  App.vue    │绑定 │  app.go      │  │
│  │  xterm 终端  │事件 │  SSH / SQLite│  │
│  └─────────────┘     └───────────────┘  │
└─────────────────────────────────────────┘
```

## 2. 安装 Wails CLI（`wails.exe` 从哪来）

`D:\golang\gopath\bin\wails.exe` **不是本项目打出来的**，也不是 `wails build` 的产物。

它是 **Wails 命令行工具（CLI）**，用来执行 `wails dev`、`wails build`。第一次（或删掉之后）用 Go 安装，会编译并生成这个 exe。

### 2.1 安装 / 重新生成

前提：本机已安装 Go，并能访问网络下载模块。

**Windows（PowerShell，任意目录）：**

```powershell
go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0
```

**macOS / Linux（终端，任意目录）：**

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0
```

这条命令会：

1. 下载 `github.com/wailsapp/wails/v2` 的 **v2.15.0**
2. 编译其中的 `cmd/wails`
3. 把生成的可执行文件放到 `%GOPATH%\bin`（Windows）或 `$GOPATH/bin`（macOS / Linux）

本机 Windows 的 `GOPATH` 是 `D:\golang\gopath`，所以生成路径是：

```
D:\golang\gopath\bin\wails.exe
```

macOS / Linux 常见路径（以 `go env GOPATH` 为准）：

```
$(go env GOPATH)/bin/wails
```

例如 `$HOME/go/bin/wails`。如果提示 `wails: command not found`，把该目录加入 `PATH`，或用绝对路径调用。

如果设置过环境变量 `GOBIN`，则会生成到 `GOBIN` 目录，而不是 `GOPATH/bin`。

本项目按 **v2.15.0** 使用，安装时请带上 `@v2.15.0`，不要随便改成 `@latest`，以免版本对不上。

### 2.2 安装成功怎么确认

**Windows：**

```powershell
& 'D:\golang\gopath\bin\wails.exe' version
```

**macOS / Linux：**

```bash
"$(go env GOPATH)/bin/wails" version
# 若已加入 PATH，也可直接：
wails version
```

应看到：

```
v2.15.0
```

如果提示找不到命令，检查：

- 文件是否存在：Windows 看 `D:\golang\gopath\bin\wails.exe`，macOS / Linux 看 `$(go env GOPATH)/bin/wails`
- `GOPATH` 是否符合预期（执行 `go env GOPATH`）
- `go install` 过程中是否有报错（网络、Go 版本过低等）

查看 GOPATH：

```powershell
# Windows PowerShell
go env GOPATH
go env GOBIN
```

```bash
# macOS / Linux
go env GOPATH
go env GOBIN
```



### 2.3 如果把 `wails.exe` 删了

- **可以删**：只是少了开发工具。
- **不影响**：项目源码、`frontend/`、已经打包好的 `build\bin\ssh-go.exe`。
- **发给别人用的成品不依赖** `wails` / `wails.exe`。
- **不能再执行**：`wails dev`、`wails build`。

需要再开发时，重新执行：

```powershell
go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0
```

即可再次生成 `D:\golang\gopath\bin\wails.exe`。

### 2.4 脚手架和成品不要搞混


| 文件                                           | 怎么来的                                                        | 干什么                    |
| -------------------------------------------- | ----------------------------------------------------------- | ---------------------- |
| `wails.exe`（Windows）或 `wails`（macOS / Linux） | `go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0` | 脚手架：开发、打包              |
| `build/bin/ssh-go.exe`                       | 在 **Windows** 上 `wails build`                               | 给 Windows 用户用的 SSH 客户端 |
| `build/bin/ssh-go.app`                       | 在 **macOS** 上 `wails build`                                 | 给 Mac 用户用的 SSH 客户端     |
| `build/bin/ssh-go`                           | 在 **Linux** 上 `wails build`                                 | 给 Linux 用户用的 SSH 客户端   |

## 3. 开发调试



### 3.1 环境要求

- Go（Wails v2.15 需要较新版本，本机曾用 Go 1.25）
- Node.js / npm
- 已按第 2 节安装好 Wails CLI（Windows：`wails.exe`；macOS / Linux：`wails`）
- 必须在项目根目录执行（有 `wails.json` 的目录）



### 3.2 启动命令

**Windows：**

```powershell
cd "E:\resource\person\ssh-go"
& 'D:\golang\gopath\bin\wails.exe' dev
```

**macOS / Linux：**

```bash
cd /path/to/ssh-go
"$(go env GOPATH)/bin/wails" dev
# 或已加入 PATH：
wails dev
```

成功后终端会打印类似：

```
Using DevServer URL: http://localhost:34115
Vite Server URL: http://localhost:5173/
To develop in the browser ... navigate to: http://localhost:34115
```



### 3.3 两个端口（务必分清）


| 端口            | 是什么        | 能否调 Go 后端                              |
| ------------- | ---------- | -------------------------------------- |
| **34115**     | Wails 调试入口 | **能**，有 `window.go` / `window.runtime` |
| 5173（或 5174…） | Vite 热更新   | **不能**，只是纯前端页面                         |


**调试请打开：[http://localhost:34115](http://localhost:34115)**

不要直接打开 Vite 端口，否则连接列表、SSH 都会失败。

### 3.4 建议调试方式

1. 保持 `wails dev` 在跑。
2. 用 **Chrome 打开 [http://localhost:34115](http://localhost:34115)**，按 F12 看 Console。
3. Network 里 **Fetch/XHR 是空的，这是正常的**：本项目不是 HTTP 接口。要看前后端调用，点 **WS →** `/wails/ipc` **→ Messages**。
4. 改 `frontend/src/App.vue` 一般会热更新。
5. 改 Go 文件（`app.go`、`internal/**`）会触发重新编译，等终端出现 `Compiling application: Done` 后再试。
6. 改 `index.html`、`vite.config.ts` 往往不会热更新，需要：
  - 终端 `Ctrl+C` 停掉 `wails dev`
  - 再重新执行上面的启动命令
  - 浏览器 `Ctrl+Shift+R` 强制刷新



### 3.5 常见问题

- **34115 被占用**：之前的 `wails dev` 或 `ssh-go-dev.exe` 没关干净，先结束进程再启动。
- **Console 里** `Overlay.svelte ... nodes`：Wails 开发遮罩问题，不是业务代码；打包 exe 后没有。
- **连接成功但终端空白**：以前是 `Shell()` 和 `Wait()` 竞态，现已修复。仍异常时看 Wails 终端是否有 `session started`。
- **数据库位置（开发时）**：默认跟「当前运行的 exe」同目录的 `data.db`。`wails dev` 时 exe 可能在临时目录或 `build/bin`，和正式包不一定是同一个库。

可用环境变量覆盖：

```powershell
# Windows
$env:DB_PATH = "E:\resource\person\ssh-go\data.db"
& 'D:\golang\gopath\bin\wails.exe' dev
```

```bash
# macOS / Linux
export DB_PATH="$PWD/data.db"
wails dev
```

## 4. 正式部署

Wails 支持 Windows / macOS / Linux，**建议在对应系统上打包**（依赖本机 WebView 和 CGO）。在 Windows 上执行 `wails build` 只会得到 Windows 的 `ssh-go.exe`，不会同时得到 Mac / Linux 包。

前端会被编译进 `frontend/dist`，再通过 `main.go` 的 `//go:embed` 打进成品。用户电脑不需要装 Node / Go，也不需要 `wails` CLI。

### 4.1 Windows 打包

在 Windows、项目根目录执行：

```powershell
cd "E:\resource\person\ssh-go"
& 'D:\golang\gopath\bin\wails.exe' build
```

产物：

```
build\bin\ssh-go.exe
```

可选：打 NSIS 安装包（需本机已装 NSIS）：

```powershell
& 'D:\golang\gopath\bin\wails.exe' build -nsis
```

发给别人：

1. 把 `ssh-go.exe` 拷到任意目录（建议单独一个文件夹）。
2. 双击运行。Win10 / Win11 一般已有 WebView2；若极老系统打不开，需安装 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。
3. 同目录会生成 / 使用 `data.db`（连接账号密码存在这里）。
4. 可选：同目录放 `config.json`。

不要只拷 exe、却把 `data.db` 落在别的机器路径上——库文件跟可执行文件走。

### 4.2 macOS 打包

在 **Mac 本机**（需 Xcode 命令行工具）：

```bash
xcode-select --install   # 若尚未安装
go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0
cd /path/to/ssh-go
"$(go env GOPATH)/bin/wails" build
```

产物：

```
build/bin/ssh-go.app
```

按芯片选择平台（都在 Mac 上执行）：

```bash
# Apple Silicon（M1 / M2 / M3…）
wails build -platform darwin/arm64

# Intel Mac
wails build -platform darwin/amd64

# 通用包（同一台 Mac 上打两种架构再合并，耗时更长）
wails build -platform darwin/universal
```

发给别人：

1. 把 `ssh-go.app` 拷到「应用程序」或任意文件夹，双击运行。
2. 若提示「无法打开，因为来自身份不明的开发者」：系统设置 → 隐私与安全性 → 仍要打开；或右键 → 打开。
3. 数据库默认在可执行文件同目录。`.app` 里实际二进制在 `ssh-go.app/Contents/MacOS/`，若放到 `/Applications` 可能没有写权限。分发时建议：
  - 把 `.app` 放在用户可写目录，或
  - 用环境变量指定库路径：`export DB_PATH="$HOME/Library/Application Support/ssh-go/data.db"`



### 4.3 Linux 打包

在 **Linux 本机**（Debian / Ubuntu 示例，需 GTK 和 WebKit 开发库）：

```bash
sudo apt update
sudo apt install -y build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev
# 若 4.1 找不到，可改试：libwebkit2gtk-4.0-dev

go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0
cd /path/to/ssh-go
"$(go env GOPATH)/bin/wails" build
```

指定架构：

```bash
wails build -platform linux/amd64
# ARM 机器上：
wails build -platform linux/arm64
```

产物：

```
build/bin/ssh-go
```

发给别人：

1. 把 `ssh-go` 拷到任意目录，赋予执行权限后运行：

```bash
chmod +x ssh-go
./ssh-go
```

1. 对方系统需有运行库（一般桌面发行版已有 GTK / WebKit）。若打不开，按发行版安装 `libgtk-3-0` 和 `libwebkit2gtk-4.1-0`（或 `libwebkit2gtk-4.0-37`）。
2. 同目录会生成 / 使用 `data.db`。可选同目录放 `config.json`。
3. 也可用环境变量：`export DB_PATH="$HOME/.local/share/ssh-go/data.db"`



### 4.4 配置（可选）

`config.json` 示例字段（见 `internal/config/config.go`）：

- `dbPath`：数据库文件路径，空则用 **可执行文件同目录** `data.db`
- `logLevel`：`DEBUG` / `INFO` / `WARN` / `ERROR`

环境变量 `DB_PATH` 优先于配置文件。

### 4.5 开发包 vs 正式包


|            | 开发 `wails dev`                       | 正式 `wails build`       |
| ---------- | ------------------------------------ | ---------------------- |
| 界面         | 可开浏览器 34115                          | 桌面窗口                   |
| 前端         | Vite 热更新                             | 打进成品                   |
| 控制台        | 浏览器 F12                              | 无浏览器调试（除非自己加日志）        |
| Windows 产物 | `build/bin/ssh-go-dev.exe`（会占 34115） | `build/bin/ssh-go.exe` |
| macOS 产物   | 开发用 app / 二进制                        | `build/bin/ssh-go.app` |
| Linux 产物   | 开发用二进制                               | `build/bin/ssh-go`     |


### 4.6 图标、清单是怎么进 exe 的

打包后发给别人往往 **只有一个 `ssh-go.exe`**，但仓库里还有：

```
build/appicon.png
build/windows/icon.ico
build/windows/info.json
build/windows/wails.exe.manifest
```

这些 **有作用**，而且就是靠它们让 exe 看起来像正常 Windows 程序。它们是 **打包输入**，不是发给用户的附件。`wails build` 时会写进 exe 的 PE 资源段，所以成品旁边看不到独立的 ico / manifest。

```
build/appicon.png                 源图标（改图标一般改这个）
        ↓ Wails 转换成 Windows 图标
build/windows/icon.ico            资源管理器里看到的 exe 图标
build/windows/info.json           右键 exe → 属性 → 详细信息（产品名、版本、版权）
build/windows/wails.exe.manifest  高分屏不模糊、用系统现代控件样式
        ↓ wails build 嵌入
build/bin/ssh-go.exe              发给别人的就这一个文件
```

| 文件 | 干什么 | 运行时还要单独放旁边吗 |
|------|--------|------------------------|
| `build/appicon.png` | 各平台图标源文件 | 不用 |
| `build/windows/icon.ico` | Windows exe 图标 | 不用，已打进 exe |
| `build/windows/info.json` | 版本信息 | 不用 |
| `build/windows/wails.exe.manifest` | DPI、视觉样式 | 不用 |
| `build/bin/data.db` | 连接账号密码 | **要**，这是运行时数据，不是打包资源 |
| `frontend/dist/` | 编好的 Vue 页面 | 不用；`main.go` 的 `//go:embed` 会打进同一个 exe |

两条线最后都进同一个 exe：

- **窗口图标 / 属性 / 清单**：走 Windows 资源（上面这些文件）
- **Vue 页面**：先编到 `frontend/dist`，再被 Go embed 进去

注意：

- **不要删** `build/windows/`。删了下次打包可能变成默认图标、没有版本信息，或高分屏发糊。
- **改图标**：改 `build/appicon.png`（或 `icon.ico`）后必须重新 `wails build`，已经打好的 exe 不会自己变。
- **发给别人**：拷 `ssh-go.exe` 即可。对方双击后，同目录会再长出自己的 `data.db`。不要把 `icon.ico`、`info.json` 一起拷过去当运行依赖。
- `build/bin/ssh-go-dev.exe` 是开发模式产物，不要发给别人。热重编时可能出现 `ssh-go-dev.exe~`，是旧进程占用时的残留，可删。

开发时库跟正在跑的 exe 走：`wails dev` 用的是 `build/bin/data.db`。项目根目录若还有一个 `data.db`，**不是同一份**（根目录那个常常是空库）。要用同一份可设 `$env:DB_PATH`。

## 5. 页面如何关联后端

本项目 **不是 HTTP 调用**（没有 `/api/xxx`，Chrome Network 的 Fetch/XHR 里看不到接口）。

- 前端：`window.go.main.App.方法名()`
- 开发时用浏览器打开 34115：走 WebSocket `/wails/ipc`
- 打包成成品后：走桌面内嵌 IPC，连 34115 都没有



### 5.1 绑定（前端主动调 Go）

`main.go` 里：

```go
Bind: []interface{}{ app },
```

Wails 会把 `app.go` 里 **首字母大写的方法** 暴露给前端，并生成：

- `frontend/wailsjs/go/main/App.js`
- `frontend/wailsjs/go/main/App.d.ts`

Vue 中这样用：

```ts
import { ListConnections, StartSession, SendSessionInput } from '../wailsjs/go/main/App'

const list = await ListConnections(false, '')
const sid = await StartSession(conn.ID)
```

本质是：`window.go.main.App.StartSession(...)`。

当前暴露的方法：


| 方法                 | 作用                     |
| ------------------ | ---------------------- |
| `ListConnections`  | 查连接列表                  |
| `AddConnection`    | 新增连接                   |
| `UpdateConnection` | 修改已有连接                 |
| `SetDeleted`       | 删除 / 恢复                |
| `StartSession`     | 建立 SSH 会话，返回 sessionID |
| `SendSessionInput` | 把键盘输入发给远端              |
| `ResizeSession`    | 同步终端宽高                 |
| `CloseSession`     | 关闭会话                   |


这些文件是 **自动生成的**，不要手改。改 `app.go` 后 `wails dev` / `wails build` 会重新生成。

### 5.2 事件（Go 主动推前端）

SSH 输出是流式的，不能只靠一次函数返回。后端读到数据后：

```go
runtime.EventsEmit(a.ctx, "terminal-output", sessionID, text)
runtime.EventsEmit(a.ctx, "terminal-closed", sessionID)
```

前端监听：

```ts
import { EventsOn } from '../wailsjs/runtime/runtime'

EventsOn('terminal-output', (sessionID, data) => {
  // 写入 xterm
})
```



### 5.3 一次「点连接」的完整链路

```
用户双击快速连接 / 连接管理器
        ↓
App.vue  onConnect()
        ↓
StartSession(connID)     ← 绑定调用 Go
        ↓
app.go  查 SQLite → sshclient 拨号、申请 PTY、启动 Shell
        ↓
返回 sessionID，前端创建 Tab + xterm
        ↓
Go 协程读 SSH stdout  → EventsEmit("terminal-output")
        ↓
Vue 写入 xterm 显示 Last login / 提示符
        ↓
用户键盘 → xterm onData → SendSessionInput → SSH stdin
```

## 6. 主要文件作用



### 根目录 / 后端


| 文件            | 作用                                     |
| ------------- | -------------------------------------- |
| `wails.json`  | Wails 工程配置：应用名、前端 install/build/dev 命令 |
| `main.go`     | 桌面程序入口：嵌入前端资源、绑定 App、启动窗口              |
| `app.go`      | **前后端交界**：给 Vue 调用的方法和 SSH 输出事件        |

## 7. 操作速查

**安装 / 找回 Wails CLI**

```powershell
# Windows
go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0
& 'D:\golang\gopath\bin\wails.exe' version
# 应输出 v2.15.0
```

```bash
# macOS / Linux
go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0
"$(go env GOPATH)/bin/wails" version
# 应输出 v2.15.0
```

**日常开发**

```powershell
# Windows
cd "E:\resource\person\ssh-go"
& 'D:\golang\gopath\bin\wails.exe' dev
# 浏览器打开 http://localhost:34115
# Network 看调用：点 WS，不要点 Fetch/XHR
```

```bash
# macOS / Linux
cd /path/to/ssh-go
"$(go env GOPATH)/bin/wails" dev
# 浏览器打开 http://localhost:34115
```

**发正式版（在对应系统上打包）**

```powershell
# Windows → build\bin\ssh-go.exe
cd "E:\resource\person\ssh-go"
& 'D:\golang\gopath\bin\wails.exe' build
```

```bash
# macOS → build/bin/ssh-go.app
cd /path/to/ssh-go
wails build
# Apple Silicon: wails build -platform darwin/arm64
# Intel:         wails build -platform darwin/amd64
```

```bash
# Linux → build/bin/ssh-go
cd /path/to/ssh-go
wails build
# 可选：wails build -platform linux/amd64
chmod +x build/bin/ssh-go
```

**改后端接口后**：改 `app.go` → 等 Wails 重新生成 `frontend/wailsjs` → 前端 import 新方法。

**改界面**：优先改 `frontend/src/App.vue`。

**改图标**：改 `build/appicon.png` 后重新 `wails build`。`icon.ico` / `info.json` / `manifest` 会打进 exe，不用随包分发。

**开发时的库**：看 `build/bin/data.db`，不要和项目根目录的 `data.db` 搞混。
