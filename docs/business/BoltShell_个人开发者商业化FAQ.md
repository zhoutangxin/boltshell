## 一、结论先看

| 问题 | 答案 |
|------|------|
| 要不要 Pro？ | **可以要，但不要做成「卖解锁」**；个人开发者优先 **低价买断 / 支持者档**，不要 ¥1/月订阅 |
| **Pro 要不要去掉赞助？** | **不要。** 赞助全员可见；Pro 卖真功能。可关闭单条推荐，**不写「去广告」**。见 §2.3 |
| 「卖解锁」是什么？ | 代码本来就能做，人为加锁，付钱才解开（限 5 连接、去广告） |
| 「卖服务 / B 端」是什么？ | 卖**边际成本真实存在**的东西：云同步、定制适配、审计、发票、支持合同——**不是**解功能锁 |
| 跨机传文件 + 终端/SFTP/监控一体 | **你已做完**；这是推广主卖点，多数 SSH 客户端没有跨机直传 |
| 产品亮点 / 还该做什么 / 怎么宣传 / Pro 清单 | **见 [产品亮点与竞品对比](BoltShell_产品亮点与竞品对比.md)**（§五～§七 权威） |
| 「又一个 SSH+SFTP」指什么 | 读者扫清单时的归类；缺密钥/加密易被忽略差异——见亮点文档 §3.5 |
| SQLite 加密存密码行不行 | **行**；用户在意拷库能否读明文——§3.6 |
| Termius 什么技术栈 | Electron + React/TS + C++ 模块；可与之对比内存 |
| FinalShell 一定有广告吗 | **勿乱写**；只说自己无弹窗/赞助可关 |
| FinalShell 一键导入 | **尚未做**；现有「导入」只导自己的 JSON。见 §三 |
| 埋点会不会伤信任？ | 会有人疑，但可控；伤信任的是**没说清 + 不可验证**，不是「有 HTTPS 请求」 |
| 主动教用户屏蔽统计域名？ | **要教**。少数会关，多数更信任；关了的人本就不愿被统计，硬采会反噬口碑与续约 |
| Navicat 联网 = 你可以联网？ | **部分对**：商业软件联网常见；但 Navicat 常被怀疑「查未付费」，你要**主动证明只传赞助元数据** |

## 二、「卖解锁」vs「卖服务 / B 端」

### 2.1 卖解锁（Sell unlock）

| 例子 | 本质 |
|------|------|
| 免费版只能存 5 个连接，Pro 无限 | 存 100 个的代码早就有，是 `if count > 5` 拦住 |
| Pro「去除广告」 | 不显示赞助位才是默认，你让它显示再卖「关掉」 |

特点：破解成本极低（改一个 bool）；开源后几乎等于白送；在「旁边有 WindTerm 全免费」时转化差。

### 2.2 卖服务（Sell service）——个人开发者该卖的

| 形态 | 用户付的是什么 | 一个人能不能扛 |
|------|----------------|-----------------|
| **支持者 / Catalyst 式买断** | 感谢开发 + 徽章 + 致谢署名（可不解锁功能） | ✅ 最轻 |
| **Pro 买断（真功能）** | Snippets、会话录制、竞品导入、分屏等**真写代码**的模块 | ✅ 可做 |
| **云 Sync 订阅** | 服务器流量 + 加密同步 | ⚠️ 有运维与安全责任，v1.5+ 再考虑 |
| **技术支持合同** | 邮件/IM 答疑 + SLA | ⚠️ 时间成本高，可偶接大单，不当主业 |
| **B 端 / 企业授权** | 发票、对公、私有化、审计日志、国产化适配（UOS/麒麟） | ⚠️ 客单价高但吃时间；有单再接，不预建大团队 |

**对你（一个人）的默认结构：**

```
Free（功能完整、赞助鸣谢可见）
  → 支持者 ¥9.9 买断（可不解锁功能）
  → Pro ¥88 买断（真功能，非「去广告 + 无限连接」当主卖点）
  → 偶发：定制 / 开票 / 企业授权（面议）
  + 云厂商 CPS + 客户端/官网赞助位
```

**不要做：** ¥1/月自动续费（个人主体难签周期扣款；续费率崩；运维成本与高价订阅一样）。

### 2.3 已定：Pro **不**去掉赞助

| 档位 | 赞助位 | 卖什么 |
|------|--------|--------|
| Free | **看得见** | 核心运维（含跨机传、监控） |
| 支持者 ¥9.9 | **看得见** + 徽章/官网致谢 | 支持开发，可不解锁功能 |
| **Pro** | **仍然看得见** | 真功能（导入、Snippets、录制等） |

折中可以：任意档 **永久关闭某条**赞助卡；文案用「关闭推荐」，**禁止**写「去广告 / 去赞助会员」。  
理由：避免卖解锁、保住赞助可售触达、与「这是赞助不是广告墙」一致。  
代码若仍 `IsPro → 隐藏全部赞助`，属旧逻辑，应改掉。详见 [产品亮点与竞品对比 §二](BoltShell_产品亮点与竞品对比.md)。

**徽章是什么：** 非实体。常见为关于页/设置里的「支持者」标识、侧栏极小标记、官网 `/thanks` 昵称列表（可匿名）。

## 三、一键导入竞品配置：以 FinalShell 为例

### 3.1 现状（代码事实）

| 能力 | 状态 |
|------|------|
| 导入 / 导出 **BoltShell 自己的** JSON 连接包 | ✅ 已有（`ImportConnections` / `app_connections_io.go`） |
| 从 **FinalShell / Xshell** 一键导入 | ❌ 未做（`docs/TODO.md` 仍勾选待办） |

用户点「导入」时选的是 **BoltShell 导出的 JSON**，不是 FinalShell 目录。  
对外宣传「一键从 FinalShell 导入」前，必须先实现解析器。

### 3.2 FinalShell 配置在哪、长什么样

FinalShell **官方故意弱化本地导入导出**（推云同步收费），但配置在磁盘上可读。常见路径（因版本可能略有差异）：

| 系统 | 常见路径 |
|------|----------|
| Windows | `%LOCALAPPDATA%\finalshell` 或 `%APPDATA%\FinalShell` |
| macOS | `~/Library/Application Support/FinalShell` |
| Linux | `~/.finalshell` |

典型内容：

| 路径/文件 | 含义 |
|-----------|------|
| `conn/` | 各会话连接信息（常加密存密码） |
| `config.json` | 全局设置 |
| `knownhosts.json` | 主机密钥 |
| `tconfig.json` | 缓存类 |

社区已有迁移工具思路：[finalshell2all](https://github.com/Sn0r1axi/finalshell2all)（读 `config.json` + `conn/`，导出到 Termius CSV / SecureCRT）。BoltShell 可参考其解析思路，**不要依赖闭源逆向协议文档**——以「读本地目录、用户知情同意」为准。

### 3.3 产品里「一键导入」应如何操作（目标体验）

```
设置 / 连接管理 →「从 FinalShell 导入」
  → 自动探测默认目录（可改选）
  → 列出将导入的主机（分组、主机、端口、用户名；密码/密钥单独提示）
  → 用户勾选确认
  → 写入 BoltShell 本地库
  → 密码：能解密则本地解密后按我们加密方案存；不能则提示用户补密或改用密钥
```

**红线：**

- 导入过程 **不上传** 任何主机/密码到我们服务器；
- UI 明确写「仅读取本机 FinalShell 目录」；
- 私钥文件只复制路径引用或经用户确认再拷贝，不静默外发。

### 3.4 Xshell

Xshell 会话多为 `.xsh` 等文件树；实现方式类似：选目录 → 解析 → 映射到我们的连接模型。优先级可放在 FinalShell 之后（国内个人用户 FinalShell 迁移需求更强）。

### 3.5 为什么这是「推广」而不只是功能

迁移成本 = 最大流失阻力。文章标题可直接写：

> 「从 FinalShell 迁到 BoltShell：一键导入连接，保留分组」

没有导入功能时，这句话是空头支票；有了之后，它同时是功能与获客素材。

## 四、跨服务器传文件 + 一体化：你已经赢在产品上

### 4.1 事实

| 能力 | BoltShell |
|------|-----------|
| 终端 + SFTP + 监控一体 | ✅ 已有 |
| **跨服务器直接传文件**（A 机 → B 机，不必先下到本机） | ✅ 已有（`useServerTransfer` / `app_sftp`） |

### 4.2 为什么多数 SSH 工具没有跨机直传

典型路径是：**服务器 A → 本机 → 服务器 B**（两次传输）。  
跨机直传要：临时连目标机、目录浏览、进度、断点/错误处理，工程量明显大于「单边 SFTP」。  
PuTTY、很多轻量客户端根本不做文件；WinSCP 偏本机↔远端；Termius / 部分产品有，但不是人人强调。

**推广含义：** 这不是「再做功能」，而是 **选定唯一主传播点**：

> 一句话：**不用先下载到电脑，服务器之间直接传文件。**

所有知乎 / V2EX / 小众软件介绍，优先打这一点 +「终端/SFTP/监控同屏」，不要同时堆十个卖点。

## 六、埋点、联网与信任（含 Navicat 类比）

### 6.1 「静默上报、没有开关、隐私政策找不到」是什么意思？

| 坏做法 | 用户感受 |
|--------|----------|
| **静默上报** | 后台一直 POST，设置里找不到、首次启动也不问 |
| **没有开关** | 想关都关不了 |
| **隐私政策找不到** | 官网/关于页没有「我们传什么」 |

这三样叠在一起 = 「偷偷监视」，比「有统计」本身伤信任得多。

**我们的正确形态：**

- 设置页：**帮助改进产品（匿名统计）** 开关；
- 首次启动：一句话说清 + 可关；
- 官网：**抓包示例 + 字段白名单**（见 §6.4）；
- 代码可审计（analytics 包路径见 §6.3）。

### 6.2 Navicat 联网：你的理解哪里对、哪里要小心

**对的部分：**  
商业桌面软件（Navicat、JetBrains、FinalShell 云同步、Termius）**几乎都会连自家服务器**——检查更新、账号、License 心跳、云同步等。  
用户抓到 HTTPS 不一定等于「窃取数据库内容」。**有联网请求本身不是原罪。**

**要小心的部分：**

| 类型 | Navicat 类常见目的 | BoltShell 赞助统计目的 |
|------|--------------------|------------------------|
| License / 未付费检测 | 查激活、设备数、是否破解 | **我们 v1 不做**（或以后离线 License，另说） |
| 产品改进统计 | 功能使用率 | **仅** app_launch + 赞助位曝光/点击/关闭 |
| 敏感业务数据 | 若传了连接串/库结构 = 翻车 | **绝对禁止**：SSH 主机/IP/命令/密码 |

所以：「Navicat 也联网，所以我也可以」→ **成立**；  
「所以传什么都无所谓」→ **不成立**。你要主动证明：**接口通讯只打赞助与启动元数据，不打运维内容。**

### 6.3 analytics 代码在哪？

| 位置 | 作用 |
|------|------|
| `boltshell/server/app_analytics.go` | Wails 暴露：`TrackSponsorEvent` / 开关 / Flush / InstallID |
| `boltshell/server/internal/analytics/` | 队列、installId、批量 POST |
| `boltshell/web/src/components/sponsor/SponsorBanner.vue` | 前端触发 impression / click |
| 用户本机 | `%LOCALAPPDATA%\BoltShell\analytics.queue`、`install.id`、`analytics.prefs.json` |
| 服务端 | `boltshell-server` → `POST /api/v1/analytics/events` |

### 6.4 官网直接提供抓包示例（强烈建议做）

页面建议结构：

1. **我们只传这些字段**（贴真实 JSON 样例，脱敏）；
2. **永不传**：主机、IP、端口、用户名、密码、密钥、命令、SFTP 路径；
3. **Wireshark / mitmproxy 怎么抓**（指向独立子域，如 `t.boltshell.com`）；
4. **如何关闭统计 / 如何 hosts 屏蔽**（见 §七）；
5. **设置里「查看我上报的数据」**（打开本地 queue）。

示例（与设计文档一致，可直接放官网）：

```json
{
  "schema": 1,
  "event": "sponsor_impression",
  "ts": "2026-08-21T16:00:00+08:00",
  "installId": "a1b2c3d4-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "appVersion": "1.0.2",
  "os": "windows",
  "isPro": false,
  "props": {
    "slotId": "sidebar_1",
    "configVersion": 1,
    "linkHost": "example.com"
  }
}
```

对外话术：

> 我们统计赞助位曝光与点击，是为了**不向赞助商虚报数字**。  
> 我们不需要、也不想知道你连了哪台服务器。

### 6.5 「也可以做接口通讯」

可以，而且**应该走正规 HTTPS API**（你们已设计的批量 `POST /api/v1/analytics/events`），不要塞进 SSH 隧道、不要混在更新通道里偷偷带。  
透明、独立子域、可屏蔽 = 信任；混装 = 抓包后无法解释。

## 七、独立子域 + 主动告知屏蔽：会不会少收益？

### 7.1 会少一点样本，但通常更划算

| | 硬采、不告知 | 独立子域 + 可关可屏蔽 |
|--|--------------|----------------------|
| 上报率 | 接近 100% | 可能 70%～95%（多数人懒得关） |
| 被扒皮后的口碑 | 崩 | 稳 |
| 赞助商续约 | 虚高一次、下次对不上 | 实数可信 |
| 你的精力 | 解释成本无限 | 文档写一次 |

**关统计的人：** 往往是最敏感、最爱发帖的那批；硬采他们 → 一张「BoltShell 偷偷上报」截图顶掉一个月推广。  
**留着的人：** 够你算 DAU/曝光趋势和谈 CPT。早期谈赞助本来就不该「保底曝光」，而应用 **CPT 包月 + UTM 自核**。

### 7.2 推荐做法

```
统计域名：https://t.boltshell.com/...   （或 analytics.boltshell.com）
赞助配置：https://boltshell.com/config/sponsors.json   （可分开）
```

关于页 / 隐私页写：

> 若不希望参与匿名统计，可在设置中关闭，或在 hosts 中屏蔽 `t.boltshell.com`。  
> **关闭后 SSH、SFTP、监控、跨机传送均不受影响。**

### 7.3 收益公式（心里要清楚）

```
赞助收入 ≈ f(真实免费活跃 × 信任 × 续约)
         ≠ f(强制 100% 上报率)
```

少 10% 样本，刊例几乎不动；丢一次信任，赞助和 Pro 一起没。

## 八、Pro 会员怎么实现：要不要用户体系？

**不要。** 个人买断走 **离线 License 文件**，不是账号登录。  
用户体系留给以后「云 Sync / Team」——现在上等于自己养登录、找回密码、验证码。

### 8.1 对照

| | 离线 License（推荐 v1） | 用户体系（账号） |
|--|-------------------------|------------------|
| 用户要做什么 | 付款 → 收到 `license.dat` → 导入客户端 | 注册、登录、改密、邮箱验证 |
| 你要养什么 | 签发密钥 + 发信/发卡 | 用户表、会话、风控、隐私合规 |
| 断网 | **能用** | 至少要能离线缓存，否则 SSH 工具翻车 |
| 适合 | 买断 Pro / 支持者 | 云同步、多设备席位、企业后台 |
| 现有代码 | `internal/license` + `%LOCALAPPDATA%\BoltShell\license.dat` | **没有，也不该现在做** |

统计上报用的 `installId` **不是用户账号**，不要拿它当会员身份。

### 8.2 推荐流程（一个人能扛）

```
用户在官网付款（微信/支付宝当面付、爱发电、Lemon Squeezy 等）
        ↓
你（或脚本）用私钥签发 license.dat
  payload: { email, plan: "pro"|"supporter", expiresAt: 0, issuedAt }
  sig: HMAC/RSA（正式上线前必须换掉现在的 pepper）
        ↓
邮件附件 / 下载链接发给用户
        ↓
客户端「导入 License」写入用户目录 license.dat
        ↓
IsPro() = 校验签名 + plan + 未过期
```

`expiresAt = 0` 表示买断不过期。支持者档可用 `plan: "supporter"`（徽章即可，不必解锁功能）。

### 8.3 和现有代码怎么接

| 已有 | 作用 |
|------|------|
| `internal/license/license.go` | 读 `license.dat`，校验签名与 `plan` |
| `license.IsPro()` | 功能开关入口（Snippets / 导入等） |
| 开发 | `BOLTSHELL_DEV=1` + `config.json` 的 `proLicensed`，或 `BOLTSHELL_PRO=1` |

**还缺（发售前要补）：**

1. 正式签名：把硬编码 `pepper` 换成 **RSA 私钥只在服务端/你本机**；客户端只内置公钥验签  
2. UI：设置页「导入 License / 查看当前 plan」  
3. 签发小工具：输入邮箱 + plan → 吐出 `license.dat`（可先手工跑，不必上商城）  
4. 收款：先人工对账发码，量上来再接支付回调自动签发  

**明确不做（v1）：** 注册登录、在线心跳查破解、强制绑机器（`machineHint` 字段已预留，先空着；绑死换电脑客服你一个人接不住）。

### 8.4 Pro 卖什么（别卖解锁）

| ❌ 不要当主卖点 | ✅ 用 License 打开的真模块 |
|----------------|---------------------------|
| 去广告、限 5 个连接 | FinalShell 导入、Snippets、会话录制、分屏… |
